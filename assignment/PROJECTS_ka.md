## DummyJSON-ის საფუძვლები

სამივე მზა პროექტი იყენებს <https://dummyjson.com>-ს, უფასო სავარჯიშო API-ს. მას არ სჭირდება არც გასაღები და არც რეგისტრაცია. დოკუმენტაცია: <https://dummyjson.com/docs>

**სია ობიექტის შიგნით მოდის**, იმ რიცხვებთან ერთად, რომლებიც pagination-ისთვის გჭირდებათ:

```json
{ "products": [ ... ], "total": 194, "skip": 0, "limit": 12 }
```

**სიას URL-ით მართავთ:**

| რა გინდათ | დაამატეთ | მაგალითი |
|---|---|---|
| ელემენტების ერთი გვერდი | `limit` და `skip` | `/products?limit=12&skip=24` არის მე-3 გვერდი |
| ყველაფერი ერთად | `limit=0` | `/products?limit=0` |
| დალაგებული სია | `sortBy` და `order` | `/products?sortBy=price&order=asc` |
| მხოლოდ ზოგიერთი ველი | `select` | `/products?select=title,price` |
| ნელი პასუხი, ჩატვირთვის შეტყობინების შესამოწმებლად | `delay` მილიწამებში | `/products?delay=3000` |

მათი კომბინირება შეიძლება, და ისინი ძებნისა და კატეგორიის URL-ებზეც მუშაობს:
`/products/search?q=phone&sortBy=price&order=asc&limit=12&skip=12`

**შეცდომები.** როცა ელემენტი ვერ მოიძებნა, სტატუსი არის `404`, body კი `{ "message": "Product with id '9999' not found" }`. გახსოვდეთ, რომ `fetch` 404-ზე შეცდომას არ ისვრის. თქვენ ამოწმებთ `response.ok`-ს.

**შენახვა იმიტირებულია.** `POST`, `PUT` და `DELETE` პასუხობენ ისე, თითქოს იმუშავეს, `POST` კი ახალ `id`-ს გაძლევთ. მაგრამ არაფერი ინახება: განაახლეთ გვერდი და თქვენი ახალი ელემენტი აღარ არის, `GET /recipes/51` კი 404-ს აბრუნებს. ეს მოსალოდნელია. თუ გინდათ, რომ ელემენტი დარჩეს, თვითონ შეინახეთ `localStorage`-ში.

**სატესტო მომხმარებლები.** შედით `POST /auth/login`-ით და body-ით `{ "username": "emilys", "password": "emilyspass" }`. მუშაობს `/users`-ის ყველა მომხმარებელი: სიაში ჩანს თითოეულის `username` და `password`.

### დეტალური ხედის აწყობის ორი გზა

**მეორე გვერდი.** ბარათი ბმულია: `<a href="recipe.html?id=7">`. `recipe.html`-ზე id-ს მისამართიდან კითხულობთ:

```js
const params = new URLSearchParams(location.search);
const id = params.get("id"); // "7"
```

**იგივე გვერდი.** ბარათზე დაჭერა მალავს სიას და აჩვენებს დეტალურ სექციას, ან გვერდის ზემოდან ხსნის ფანჯარას.

ორივე სრულ ქულას იღებს. აირჩიეთ ერთი.

## პროექტი 2 — სოციალური ქსელი

Social Feed. პატარა სოციალური ქსელი. სტუმარი კითხულობს პოსტების ლენტას, ხსნის პოსტს კომენტარების სანახავად, სტუმრობს ავტორის პროფილს, შედის სისტემაში, წერს კომენტარს და ინახავს პოსტებს მოგვიანებით წასაკითხად.

API-ის დოკუმენტაცია: <https://dummyjson.com/docs/posts>, <https://dummyjson.com/docs/comments>, <https://dummyjson.com/docs/users>, <https://dummyjson.com/docs/auth>

## მეტი იდეა DummyJSON-ით

უფრო მოკლე აღწერები. თუ რომელიმეს აირჩევთ, მითხარით, და შევთანხმდებით, რას ნიშნავს შეფასების თითოეული პუნქტი თქვენს აპლიკაციაში.

### დავალებების მენეჯერი (Task Manager)

`/todos`-ში 254 დავალებაა: `{ id, todo, completed, userId }`. დავალებას ამატებთ `POST /todos/add`-ით, ნიშნავთ შესრულებულად `PUT /todos/1`-ით, შლით `DELETE /todos/1`-ით. ერთი მომხმარებლის დავალებებს აჩვენებთ `/todos/user/13`-ით (6 დავალება). ფილტრი: ყველა, აქტიური, შესრულებული.

- **აქ ადვილია:** D კატეგორია. ყველა ტიპის მოთხოვნას იყენებთ.
- **აქ უფრო რთულია:** B2 და C1. დავალებას მხოლოდ ოთხი ველი აქვს და ძებნის endpoint არ არსებობს, ამიტომ დეტალური ხედი არის მომხმარებლის პროფილი თავისი დავალებებით, ძებნა კი JavaScript-ით კეთდება.

### ადამიანების ცნობარი (People Directory)

`/users`-ში 208 ადამიანია. ძებნა: `/users/search?q=John` (3 შედეგი). ფილტრი: `/users/filter?key=hair.color&value=Brown` (23 შედეგი). დალაგება: `?sortBy=age&order=desc`. პროფილის ხედში შეიძლება ჩანდეს ადამიანის პოსტები (`/users/1/posts`) და დავალებები (`/users/13/todos`). დაამატეთ შესვლა და ხედი „ჩემი პროფილი“, რომელიც იყენებს `GET /auth/me`-ს token-ით, როგორც მე-14 ვორქშოფზე.

- **აქ ადვილია:** B და C. მონაცემები მდიდარია, API-ს კი ძებნაც შეუძლია, ფილტრიც და დალაგებაც.
- **აქ უფრო რთულია:** E. თქვენ უნდა გადაწყვიტოთ, რას ინახავს სტუმარი: კარგად მუშაობს სია „ჩემი გუნდი“.

### ციტატების კედელი (Quote Wall)

`/quotes`-ში 1454 ციტატაა: `{ id, quote, author }`. `/quotes/random` ერთ შემთხვევით ციტატას გაძლევთ.

- **აქ ადვილია:** B1 და E. ციტატების ბარათების კედელი რჩეულებით.
- **აქ უფრო რთულია:** C და D. არ არსებობს არც ძებნის endpoint და არც `POST`, ამიტომ ძებნა და ავტორით ფილტრი JavaScript-ით კეთდება, D-სთვის კი ამატებთ DummyJSON-ის შესვლას.

**გასაღებების შესახებ.** თქვენი JavaScript საჯაროა. ნებისმიერს, ვინც თქვენს საიტს გახსნის, შეუძლია წაიკითხოს მასში ჩაწერილი გასაღები. გამოიყენეთ API, რომელსაც გასაღები არ სჭირდება, ან უფასო გასაღები, რომელიც საჯაროდ გამოსაყენებლად არის განკუთვნილი. არასდროს შეიტანოთ commit-ში გასაღები, რომელიც ფული ღირს ან პირად ანგარიშს ეკუთვნის.
