## 1. აირჩიეთ პროექტი

არის სამი მზა პროექტი. სამივე იყენებს [DummyJSON](https://dummyjson.com)-ს — API-ს, რომელსაც ვორქშოფებიდან უკვე იცნობთ.

| პროექტი | რას აწყობთ |
|---|---|
| **რეცეპტების წიგნი** (Recipe Book) | კულინარიული საიტი: რეცეპტების დათვალიერება, ერთი რეცეპტის გახსნა ინგრედიენტებითა და მომზადების ნაბიჯებით, რჩეულების შენახვა, საკუთარი რეცეპტის დამატება |
| **სოციალური ქსელი** (Social Feed) | პატარა სოციალური ქსელი: პოსტების ლენტა, კომენტარები, მომხმარებლების პროფილები, ავტორიზაცია, შენახული პოსტები |
| **ონლაინ მაღაზია** (Online Store) | მაღაზია: პროდუქტების კატალოგი, პროდუქტის გვერდი შეფასებებით, კალათა, შეკვეთის გაფორმება |

ან მოიფიქრეთ **საკუთარი იდეა** და გამოიყენეთ სხვა უფასო API: ამინდის აპლიკაცია, სერიალების საძიებო, Pokédex. [PROJECTS_ka.md](PROJECTS_ka.md)-ში ნახავთ მეტ იდეას, ჩვენ მიერ შემოწმებული უფასო API-ების სიას და საკუთარი იდეის წესებს. საკუთარ იდეას დაწყებამდე ჩემი თანხმობა სჭირდება.

ყველა პროექტით ერთი და იმავე ქულის მიღება შეიძლება. აირჩიეთ ის, რომლის აწყობაც გაგიხარდებათ.

## 2. წესები

- **საკუთარი JavaScript.** არანაირი React, Vue, jQuery ან სხვა JavaScript ბიბლიოთეკა თუ ფრეიმვორკი. ყველაფერი, რასაც თქვენი აპლიკაცია მონაცემებთან აკეთებს — წამოღება (fetch), გვერდის აწყობა, ძებნა, შენახვა — თქვენი დაწერილი JavaScript-ია.
- **სტილისთვის Tailwind ან Bootstrap დაშვებულია.** დაშვებულია Bootstrap-ის საკუთარი სკრიპტიც ისეთი კომპონენტებისთვის, როგორიცაა modal და dropdown. ფონტებისა და აიქონების CDN-იდან ჩატვირთვაც შეიძლება.
- **მუშაობს Live Server-ით.** ინსტალაციისა და build-ის ნაბიჯის გარეშე. ეს Tailwind-სა და Bootstrap-საც ეხება: ჩატვირთეთ ისინი CDN-იდან `<link>` ან `<script>` თეგით და არა npm-ით.
- **მონაცემები API-დან მოდის.** რეცეპტებს, პოსტებსა და პროდუქტებს ხელით ნუ ჩაწერთ HTML-ში ან JavaScript-ში.
- **საკუთარი რეპოზიტორია.** არა fork და არა pull request. იხილეთ ნაწილი 4.
- **ყველა ხაზის ახსნა შეგიძლიათ.** იხილეთ ნაწილი 7.

## 4. შექმენით თქვენი რეპოზიტორია

ეს დავალებებისგან განსხვავდება. პროექტი ცხოვრობს რეპოზიტორიაში, რომელიც თქვენია.

1. გახსენით <https://github.com/JavaScriptADI/javascript-205-final-project>.
2. დააჭირეთ მწვანე ღილაკს **Use this template**, შემდეგ **Create a new repository**. Fork-ს ნუ გააკეთებთ.
3. Owner: თქვენი ანგარიში. Name: მაგალითად `js205-recipe-book`. Visibility: **Public**. დააჭირეთ **Create repository**.
4. დაკლონეთ **თქვენი** რეპოზიტორია და გახსენით ფოლდერი VS Code-ში:

   ```
   git clone https://github.com/<your-username>/<your-repository>.git
   ```

5. შექმენით `index.html`, `style.css` და JavaScript ფაილები რეპოზიტორიის ძირში, `README.md`-ის გვერდით.
6. გახსენით `index.html` Live Server-ით.

თქვენს ახალ რეპოზიტორიაში უკვე არის ეს ფაილები:

| ფაილი | რა არის | შეგიძლიათ შეცვალოთ? |
|---|---|---|

სტრუქტურა, რომელიც კარგად მუშაობს:

```
index.html

  api.js       ფუნქციები, რომლებიც მონაცემებს იღებენ (fetch) და აბრუნებენ
```

### Commit-ები

თქვენი commit-ების ისტორია ფასდება. მან უნდა მოყვეს, როგორ იზრდებოდა პროექტი.

- გააკეთეთ commit ყოველთვის, როცა ერთი პატარა რამ ამუშავდება. ყოველი სამუშაო დღის ბოლოს გააკეთეთ push.
- ერთი commit — ერთი ცვლილება.
- შეტყობინება ამბობს, რა შეიცვალა, და ზმნით იწყება. დაწერეთ ინგლისურად.

| კარგი | ცუდი |
|---|---|
| `Add recipe cards to the home page` | `update` |
| `Show an error message when the request fails` | `fix` |
| `Fix Next button staying enabled on the last page` | `final version 2` |
| `Save favorites in localStorage` | `asdf` |

გჭირდებათ სულ მცირე **15 commit სულ მცირე 4 სხვადასხვა დღეს**. ბოლო საღამოს გაკეთებული ერთი უზარმაზარი commit ამ კატეგორიაში თითქმის არაფერს იღებს, თუნდაც აპლიკაცია იდეალური იყოს.

## 6. AI-ს გამოყენება

AI-ს გამოყენება შეგიძლიათ. არსებობს წესები.

თქვენს რეპოზიტორიაში არის ფაილი `AGENTS.md`. AI აგენტები, მაგალითად Command Code, მას ავტომატურად კითხულობენ. ის აგენტს ეუბნება:

- **ყველა თქვენი მოთხოვნა სიტყვასიტყვით ჩაწეროს `AI_LOG.md`-ში**;
- აგიხსნათ, მოგცეთ მინიშნებები და გადახედოს თქვენს კოდს;
- ერთ ჯერზე დაწეროს ერთი პატარა ფუნქცია, და მხოლოდ მას შემდეგ, რაც აღწერთ, რა უნდა გააკეთოს ამ ფუნქციამ;
- **უარი თქვას** მთლიანი პროექტის, მთლიანი გვერდის ან მთლიანი ფუნქციონალის თქვენ მაგივრად აწყობაზე.

თქვენი მხრიდან:

- ნუ წაშლით `AGENTS.md`-სა და `AI_LOG.md`-ს, ნუ შეცვლით `AGENTS.md`-ის 1–5 ნაწილებს და ლოგის ჩანაწერებს. Git ამ ფაილების ყველა ცვლილებას აჩვენებს. საკუთარი წესების დამატება შეგიძლიათ ნაწილში „My rules“.
- `AI_LOG.md` კოდთან ერთად შეიტანეთ commit-ში.
- თუ ბრაუზერის ჩატის AI-ს იყენებთ (ChatGPT, Claude, Gemini), იგივე წესები მოქმედებს და ჩანაწერებს იმავე ფორმატით თქვენ თვითონ წერთ.
- თუ AI-ს არ იყენებთ, `AI_LOG.md` დატოვეთ ისე, როგორც არის. AI-ს გამოყენებისთვის ქულა არ გაკლდებათ და მის გარეშე მუშაობისთვის არ გემატებათ.

AI-ს გამოყენება თაღლითობა არ არის. მისი დამალვა — არის. ხოლო კოდი, რომლის ახსნაც არ შეგიძლიათ, არ ითვლება — იხილეთ შემდეგი ნაწილი.

- მივუთითებ ფუნქციაზე და გკითხავთ, რას აკეთებს თითოეული ხაზი;
- გკითხავთ „რა მოხდება, თუ…“: სერვერი 404-ს დააბრუნებს, ძებნა ვერაფერს იპოვის, `localStorage` ცარიელია;
- გთხოვთ ადგილზე ერთ პატარა ცვლილებას, მაგალითად „გვერდზე 12-ის ნაცვლად 8 ელემენტი აჩვენეთ“.

**თუ თქვენი კოდის რომელიმე ნაწილს ვერ ახსნით, კარგავთ იმ კატეგორიის ქულებს, რომელსაც ეს ნაწილი ეკუთვნის.** თუ თქვენს pagination-ს ვერ ახსნით, C კატეგორია შეუსრულებლად ჩაითვლება, მაშინაც კი, თუ ის მუშაობს.

ამიტომაც აზრი არ აქვს, პროექტი სხვა ადამიანს ან AI-ს დააწერინოთ. მარტივი კოდი, რომელიც გესმით, სჯობს ჭკვიანურ კოდს, რომელიც არ გესმით.
